## 产品视角 评审意见

### 严重问题（必须修改）

**1. 【位置】** 第3.2节 默认作息表

**【问题】** 标注为"推测值，用户将来自改"，但缺少首次使用引导机制

**【原因】** 用户首次打开面对一堆默认推测值，不知道哪些需要改、怎么改，可能直接使用不准确的默认值，体验不佳

**【建议】** 添加"首次使用引导"：
- 首次启动时显示引导面板："检测到默认作息，是否根据您的实际情况调整？"
- 提供"快速配置"向导，逐步引导设置起床时间、睡觉时间、关键活动
- 允许用户选择"使用默认"或"自定义配置"

---

**2. 【位置】** 第4.4节 临近睡觉降亮度（已删除但待确认）

**【问题】** 该节已从 v3 中删除（用户选 B 砍掉），但文档中未显式标注此决策

**【原因】** 后续阅读者不知道这是"讨论后决定不做"还是"忘了写"，可能重新提出

**【建议】** 在"明确不做（v1）"列表（§11）中显式增加一条：
> ❌ 临近睡觉自动降亮度（讨论后决定不在 v1 实现）

---

### 建议优化（建议修改）

**1. 【位置】** 第7节 多设备同步与存储

**【问题】** 缺少"配置冲突"处理策略

**【原因】** 多设备同时修改配置时可能产生冲突（如手机和平板同时编辑同一节点），需要明确处理规则

**【建议】** 补充：
- 采用"最后写入胜出"策略（Last Write Wins），配置带时间戳
- 接收端收到更新时，用时间戳判断是否比自己新，新则覆盖
- 家长面板保存成功后显示"配置已同步"提示

## 研发视角 评审意见

### 严重问题（必须修改）

**1. 【位置】** 第6节 交互规格

**【问题】** 拖拽节点的时间吸附逻辑未明确

**【原因】** 规格提到"自动吸附整点/半点（可关吸附做分钟微调）"，但缺少具体交互细节：
- 吸附阈值是多少？
- 关闭吸附后分钟级微调的步长是多少？
- 拖拽过程中是否实时显示目标时间？

**【建议】** 补充交互细节：

```markdown
- 吸附模式（默认）：
  - 拖拽释放时，若距离最近整点/半点 ≤5 分钟，自动吸附
  - 拖拽过程中半透明预览，标注目标时间
- 微调模式（开关控制）：
  - 关闭吸附后，以 1 分钟为步长
  - 拖拽过程中实时显示精确时间（如 "08:23"）
```

---

**2. 【位置】** 第7.1节 架构

**【问题】** 口令验证流程缺少"首次访问"和"未设口令"两个场景

**【原因】** 规格提到"新设备首次访问需输入"，但未说明：
- 如何判断"首次访问"？
- 家长从未设过口令时，新设备的行为？

**【建议】** 补充完整流程：

```markdown
首次访问判定：
- localStorage 存 `deviceVerified: true` 标记
- 标记不存在 = 首次访问

验证流程：
1. 调用 /api/check-password-required
2. 未设口令 → 直接访问，自动标记已验证
3. 已设口令 → 显示输入界面
4. 输入口令 → 调用 /api/verify-password
5. 成功 → 标记 localStorage，进入主界面
6. 失败 → 错误提示，允许重试
```

---

### 建议优化（建议修改）

**1. 【位置】** 第5节 提醒方式

**【问题】** 缺少"多设备提醒去重"实现细节

**【原因】** 多设备同时开着时，同一节点可能在多台设备上同时响，需要去重

**【建议】** 补充：
- 服务端按 `(日期 + 节点ID + 提醒类型)` 记录已提醒
- 设备触发前查询服务端是否已提醒
- 采用乐观策略：设备先响，后同步状态（避免网络延迟影响体验）

## 测试视角 评审意见

### 严重问题（必须修改）

**1. 【位置】** 第10节 边界条件清单

**【问题】** 缺少"跨时区"和"系统时间被手动修改"两个场景

**【原因】** 用户可能携带设备跨时区旅行，或手动改了系统时间，时间轴需要正确处理

**【建议】** 补充：

```markdown
| # | 边界条件 | 处理 |
|---|---------|------|
| 13 | 设备时区变化 | 时间轴基于设备本地时间，时区变化后自动重新计算游标位置，节点配置不变 |
| 14 | 系统时间被手动修改 | 游标跟随系统时间，不做校准；提醒基于系统时间触发，可能出现提前/延后 |
```

---

**2. 【位置】** 第11节 之后（缺失）

**【问题】** 缺少"性能指标"定义

**【原因】** 无性能基准，无法量化验证"流畅体验"是否达标

**【建议】** 新增 §12（原 §12-13 顺延）：

```markdown
## 性能指标

| 指标 | 目标值 | 测量方法 |
|------|--------|----------|
| 首屏加载时间 | ≤2 秒 | 从打开页面到时间轴渲染完成 |
| 游标更新延迟 | ≤100ms | 从系统时间变化到游标位置更新 |
| 配置同步延迟 | ≤1 秒 | 从 A 设备修改到 B 设备收到更新 |
| 内存占用 | ≤100MB | Chrome DevTools 测量 |
```

---

### 建议优化（建议修改）

**1. 【位置】** 第9节 从 Tot Clock 复用的部分

**【问题】** 缺少"复用代码的验证策略"

**【原因】** 复用代码直接搬过来，需要验证在新架构下是否正常工作

**【建议】** 补充验证策略表：

```markdown
| 复用模块 | 验证重点 | 验证方法 |
|---------|---------|---------|
| 时间漂移补偿 | 页面后台返回后时间是否正确 | 模拟后台 5 分钟后返回，验证游标位置 |
| 三层持久化 | 配置是否丢失 | 清除 localStorage 后重新加载，验证从服务端恢复 |
| Wake Lock | 屏幕是否保持常亮 | 长时间运行，检查屏幕状态 |
| 长按防误触 | 长按 2 秒才触发 | 快速点击、长按 1 秒、长按 3 秒分别测试 |
| 拖拽排序 | 拖拽后顺序和进度是否正确 | 拖拽节点到不同位置，验证顺序和配置同步 |
```
