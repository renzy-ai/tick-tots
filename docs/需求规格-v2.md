## 2. 时间精度：自适应递增（需求 1 的解答）

核心思路：**前面看大概，临近睡觉看精确**。随剩余时间自动切换精度档位。

### 2.1 节点粒度
每个节点可设任意时间（07:00 / 07:30 / 07:40 均可）。
时间轴按真实时长**等比渲染**——半小时的格子就是一小时格子的一半宽。

### 2.2 显示精度档位

| 剩余时间 | 显示内容 | 视觉强度 |
|---------|---------|---------|
| > 2 小时 | `还有 4 小时` | 常规字号，正常色 |
| 30 分 ~ 2 小时 | `还有 1 小时 20 分` | 常规字号，正常色 |
| 10 ~ 30 分钟 | `还有 25 分钟` | 字号放大 1.2 倍，色温开始转暖 |
| **≤ 10 分钟** | **`还有最后 10 分钟`** | **字号 1.6 倍 + 脉冲动画 + 变色** |
| **≤ 5 分钟** | **`还有最后 5 分钟`** | **字号 2 倍 + 强脉冲 + 红橙色** |
| ≤ 1 分钟 | `还有 45 秒` | 逐秒读数 |

文案用「**还有最后 X 分钟**」这个说法（你原话），比「还剩 X 分钟」更有紧迫感。

### 2.3 档位可配置
每档的**阈值和文案**都放在家长面板里可调，不写死。
比如你觉得 10 分钟太早，可以改成 15 分钟开始提醒。

## 3. 时间与节点

### 3.1 一天的结构

```
【起床时间 可设】→【中间活动 完全自定义】→【睡觉时间 可设】
         ↑                                        │
         └──────────── 蓝色睡觉弧（跨夜）──────────┘
```

- 起床时间、睡觉时间**都可任意设置**
- 中间活动内容**完全自定义**（数量、顺序、时长、图标、颜色）
- 睡觉弧从睡觉时间连回起床时间，形成 24 小时闭环

## 4. 视觉与配色规范（UI 重点）

给 2-3 岁孩子看，配色原则：

### 4.1 颜色按「类别」编码，不是每个活动一个色

超过 6 种颜色就是视觉噪音。**按类别归并**：

| 类别 | 色系 | 色值 | 活动 |
|------|------|------|------|
| 进食 | **暖橙** | `#F59E0B` | 早饭、午饭、晚饭、点心 |
| 睡眠 | **冷蓝** | `#3B82F6` | 睡觉、午睡、起床 |
| 玩耍/自由 | **草绿** | `#22C55E` | 玩玩具、户外 |
| 卫生 | **青** | `#14B8A6` | 刷牙、洗澡、洗手 |
| 学习 | **紫** | `#A855F7` | 绘本、英语、拼图 |
| 外出 | **天蓝** | `#0EA5E9` | 上学、放学 |

### 4.2 「必须做 vs 自由」的区分

**用边框样式，不用额外角标**（你选的方案）：

| 类型 | 表现 |
|------|------|
| 必须做的事 | **实线粗边框**（3px）+ 图标饱满 |
| 自由时间 | **虚线边框**（2px dashed）+ 图标略淡 |

理由：2-3 岁不识字，边框样式是**不依赖文字**的差异信号；再加角标反而增加视觉负担。

### 4.3 三态（过去 / 现在 / 未来）

| 状态 | 表现 |
|------|------|
| 已过去 | 去饱和 + 变灰 + 图标半透明 |
| 当前 | 原色 + 高亮描边 + 轻微呼吸动画 |
| 未来 | 饱满原色 |

### 4.4 临近睡觉自动「降亮度」（💡 建议新增）

随时间接近睡觉时间，屏幕**逐渐变暗、色调转冷**：

| 距睡觉 | 屏幕表现 |
|--------|---------|
| > 2 小时 | 100% 亮度，暖色调 |
| 1 ~ 2 小时 | 85% 亮度 |
| 30 分 ~ 1 小时 | 70% 亮度，开始转冷 |
| < 30 分钟 | 50% 亮度，冷色调 |

理由：用**光线本身**作为"该睡了"的信号，比任何文字都直观，也符合生理规律（光线抑制褪黑素）。这条是我加的，你觉得不合适可以砍。

### 4.5 其他 UI 原则

- ✅ 大色块、高对比（幼儿视力仍在发育）
- ✅ 图标够大（至少 48px）
- ✅ 不用深色模式（白天要亮）
- ❌ 不用霓虹/渐变/发光（刺眼）
- ❌ 一屏颜色不超过 6 种

## 5. 提醒方式（需求 3）

| 项 | 规格 |
|----|------|
| **技术** | **Web Audio API `OscillatorNode`**，代码生成蜂鸣，**零音频文件、零依赖** |
| **音效** | 三短音「嘀-嘀-嘀」（1000Hz，每声 150ms，间隔 100ms） |
| **提前提醒** | 节点前 5 分钟响一次（单短音，轻） |
| **节点提醒** | 节点整点响一次（三短音） |
| **关闭** | 家长面板开关，**每台设备独立控制** |
| **静音时段** | 睡觉弧内不响 |

> 比 TTS 方案更好：零依赖、无音色问题、无后台语音合成开销、可直接调音高和节奏。

## 7. 多设备同步与登录（⚠️ 待你决策）

### 7.1 两种方案的代价对比

| | **方案 A：局域网同步** | **方案 B：云端 + 登录** |
|---|---|---|
| 服务器 | 家里电脑 / 挂墙设备本机 | 需**公网服务器**（24h 在线 + HTTPS） |
| 数据库 | 本机 JSON 文件 | 需数据库（Postgres / SQLite） |
| 账号体系 | 不需要（可选共享访问口令） | 需注册/登录/密码重置/安全防护 |
| 数据位置 | **不出家门** | 上云 |
| 外网访问 | ❌ 只能在家 WiFi 下 | ✅  anywhere |
| 持续成本 | **0** | 服务器费用 + 运维 |
| 复杂度 | 低 | 高 |

### 7.2 我的建议：分阶段

**Phase 1（现在做）— 局域网同步，零登录**
- 手机和挂墙平板连同一 WiFi，改配置秒同步（SSE 推送）
- 可选加一个**共享访问口令**（不是账号体系，就一个密码）防误入
- 架构上把存储层抽象成 `StorageAdapter` 接口，现在实现 `LanAdapter`

**Phase 2（真需要时再加）— 换云端**
因为存储层已抽象，**换云端只改一个 adapter 文件**，前端不用动。

云端选型（届时再定）：

| 选项 | 优势 | 适用 |
|------|------|------|
| **腾讯云开发 CloudBase** | 国内快，**天然打通微信小程序**，登录可接微信 | **若确定要做小程序，选这个** |
| **Supabase** | 开源，Postgres + Auth + Realtime，免费额度够，接入最快 | 只做网页，选这个 |
| 自建 Node + SQLite | 最可控 | 最费事，不推荐 |

### 7.3 一个关键洞察

因为是**挂钟模型**而非倒计时模型，**时间游标每台设备用自己的系统时钟算，不需要同步**。
需要同步的只有「配置」这一份数据——所以同步压力极小，Phase 1 → Phase 2 的迁移成本也很低。

## 8. 形态选择（⚠️ 待你决策）

### 8.1 五种形态对比

| 形态 | 免安装 | 后台报时可靠 | 成本 | 门槛 |
|------|--------|------------|------|------|
| ① **网页**（浏览器打开） | ✅ | ❌ 切后台就停 | 0 | 无 |
| ② **PWA**（加到桌面/主屏） | ✅ | ⚠️ 桌面可靠，iOS 不可靠 | 0 | 无 |
| ③ **桌面应用**（Tauri/Electron） | ❌ | ✅ 可靠 | 0 | 无需上架 |
| ④ **iOS App** | ❌ | ✅ 可靠 | **¥688/年 + 必须有 Mac** | App Store 审核 |
| ⑤ **微信小程序** | ✅ | ⚠️ 受限 | 0（个人免费） | 微信审核 + **代码要重写** |

### 8.2 三个必须知道的硬事实

**① iOS App 你做不了——除非买 Mac**
Apple Developer Program **$99/年（约 ¥688）**。但真正的门槛是：**Xcode 只能跑在 macOS 上**，Windows 无法开发 iOS。
你目前是 Windows 11 Home。要上 iOS 必须：买 Mac（Mac Mini 起 ~¥3000）或租云 Mac（$40-80/月）。

**② 微信小程序代码要重写**
小程序用的是 WXML/WXSS，**不是标准网页**。现在这套 Svelte 代码**不能直接用**，等于前端重做一遍。
好消息：个人主体注册**免费**（无企业那 300 元认证费），工具类目可过审。

**③ PWA 在 iOS 上后台完全不执行**
iOS 不支持 Background Sync / Periodic Background Sync。页面不可见 = JS 停 = **定时器不跑**。
所以 iPhone 上「到点滴滴滴」不可靠（除非走 Push 通知，但那需要服务器 + iOS 16.4+ + 已加到主屏）。

### 8.3 我的建议

**核心判断：挂墙设备是「常亮常显」的，页面一直在前台——这种情况下网页/PWA 完全够用。**

「后台报时」这个问题只在你把设备切走或锁屏时才存在。而挂墙时钟本来就是一直亮着的。

所以推荐路径：

```
现在：① 网页 + ② PWA（加到桌面/主屏，全屏无地址栏）
       ↓ 用起来，验证效果
如果确实需要后台可靠报时：③ Tauri 桌面应用（免费，无需上架）
       ↓ 如果想在手机上用且要小程序
远期：⑤ 微信小程序（届时需重写前端）
```

**iOS App 我建议直接放弃**——为了给孩子看个时钟，花 ¥688/年 + 买台 Mac，性价比太低。

| 模块 | 处理 | 说明 |
|------|------|------|

## 10. 边界条件清单

| # | 边界条件 | 处理 |
|---|---------|------|
| 1 | 跨夜（睡觉 20:30 → 次日 07:30） | 闭环处理 wrap-around |

| 10 | 半小时间隔取整 | 内部统一用「分钟」存储，显示层再换算 |
