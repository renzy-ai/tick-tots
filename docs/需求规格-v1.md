## 1. 核心概念模型

先统一语言，避免后面鸡同鸭讲。

| 术语 | 定义 |
|------|------|
| **节点 Node** | 时间轴上的一个时间点 + 该时刻要做的事。如「18:00 吃晚饭 🍽️」 |
| **格 Cell** | 节点占据的可视方块。默认 1 小时 = 1 格 |
| **直条 Bar** | 从「起床」到「入睡」的横向时间条，黄色系格子 |
| **睡觉弧 Arc** | 从「入睡」跨夜连回「起床」的蓝色弧线，代表夜晚 |
| **游标 Cursor** | 当前时间在时间轴上的位置指针，随时间实时移动 |
| **闭环 Loop** | 直条（白天）+ 弧（夜晚）= 完整 24 小时，**首尾相接** |

**关键设计**：这是一条**闭环 24 小时时间轴**，不是一个有头有尾的列表。
游标白天走直条，夜晚走弧，永不停止 —— 这就是"时间是流动的、不是静态的"的视觉化。

## 2. 界面规格

### 2.1 整体布局（直条 + 弧形桥接）

```
                     ☀️ 白天直条（黄色格子）
    ┌────┬────┬────┬────┬────┬────┬────┬────┐
    │ 🛏️ │ 🥣 │ 🧸 │ 🏫 │ 🍽️ │ 🛁 │ 🦷 │ 🌙 │
    │起床│早饭│ 玩 │幼儿│晚饭│洗澡│刷牙│入睡│
    │07:0│07:3│08:3│09:0│18:0│20:0│20:2│20:3│
    └────┴────┴────┴────┴────┴────┴────┴──┬─┘
       ▲                                    │
       │                                    │
       │      🌙 睡觉弧（蓝色，跨夜）        │
       └────~~~~~~~~~~~~~~~~~~~~~~~~~~~~────┘
              「已睡 5 小时 / 还有 5 小时起床」
```

- **直条**：从左（起床）到右（入睡），格子按时间**等宽**（默认每小时一格）
- **睡觉弧**：从右端（入睡）出发，向**下方**画一条弧线，绕回左端（起床）
  - 蓝色系渐变，区别于白天的黄色
  - 弧线上显示睡眠进度
- 整条时间轴**横屏铺满**，适合挂墙平板

### 2.2 时间状态可视化（需求 5 的核心）

用**三种视觉状态**区分过去/现在/未来：

| 状态 | 视觉表现 |
|------|---------|
| **已过去** | 格子变灰 + 降饱和度 + 图标半透明（"用掉了"） |
| **当前** | 高亮描边 + 轻微呼吸动画 + **游标竖线**停在该格 |
| **未来** | 原色（黄），饱满 |

**游标**：一条贯穿上下的竖线（或一个小三角指针），位置 = 当前时间。
因为按分钟移动，游标是**平滑滑动**的，不是跳格 —— 孩子能看见它"在走"。

### 2.3 剩余时间显示

屏幕顶部或底部的大字，两行：

```
还剩 3 小时 20 分钟     ← 主显示（距下一个「必须做」的节点）
还剩 3.3 格              ← 副显示（格子数，给孩子数）
```

- 提供 **小时 / 分钟** 显示切换（需求 5）
- 「还剩几个格子」用**整数 + 小数**表达，让孩子能数格子
- 在睡觉弧上时，显示「距起床还有 X 小时」

### 2.4 颜色体系

| 类别 | 颜色 | 说明 |
|------|------|------|
| 白天格子 | 黄色系 `#fbbf24` → `#f59e0b` | 对应你视频里的黄色时间条 |
| 睡觉弧 | 蓝色系 `#6366f1` → `#4338ca` | 对应视频里的"两端睡觉区" |
| **必须做的事** | 格子加**深色边框 + 锁形角标** | ⚠️ **建议增加**：呼应你视频里"吃饭洗澡刷牙必须做" |
| 自由时间 | 无边框 | 想玩哪个玩哪个 |

> 💡 我把你视频里的核心教学法（必须做 vs 自由）也做进视觉里了。
> 这样孩子一眼能看出"这几格是不能跳过的"。**这条是我加的，你如果觉得多余可以砍掉。**

## 3. 节点数据模型

### 3.1 数据结构

```ts
interface TimelineNode {
  id: string;
  time: string;          // "07:30" 挂钟时间（24h制）
  durationMin: number;   // 时长（分钟），默认 60
  label: string;         // 显示文案，如 "吃晚饭"
  icon: string;          // emoji，如 "🍽️"
  color: string;         // 格子颜色
  required: boolean;     // 是否"必须做的事"
  announce: boolean;     // 到达时是否播报
}

interface SleepBlock {
  startTime: string;     // "20:30"
  endTime: string;       // "07:00"（次日）
  label: string;         // "睡觉时间"
  icon: string;          // "🌙"
}
```

**与 Tot Clock 的关键差异**：Tot Clock 只有 `duration`（顺序倒计时，不知道几点）；
本项目用**挂钟锚点 `time`** —— 这是能实现"已过去/剩余"可视化的前提。

## 5. 播报提醒规格（需求 4）

| 项 | 规格 |
|----|------|
| **技术方案** | 浏览器原生 `speechSynthesis`（Web Speech API），**零依赖**，支持中文 |
| **播报内容** | 节点标签 + 引导语，如「该吃晚饭啦」「再过 5 分钟就要刷牙了」 |
| **提前提醒** | 到达前 **5 分钟**播报一次「还有 5 分钟就要 XXX 了」 |
| **整点播报** | 到达节点时播报「该 XXX 啦」 |
| **视觉配合** | 播报时当前格子放大脉冲 + 屏幕边框闪烁（不依赖声音也能感知） |
| **静音时段** | 睡觉弧内不播报（避免半夜出声） |

**已知限制（必须提前告诉你）**：
1. 浏览器要求**用户先有过交互**才能出声 → 首次打开需要点一下屏幕"激活声音"
2. iOS Safari 限制更严，语音必须在用户手势的调用栈里初始化
3. 网页切到后台时 TTS 会被暂停 → 如果平板息屏或切走，可能漏播
   - 缓解：Wake Lock 保持常亮；必要时配合系统通知兜底
4. 浏览器 TTS 音色一般（机械感）。**如果你想要真人语音，需要预录音或接云端 TTS** —— 要不要上云端，你定

## 6. 多设备同步方案（技术决策）

### 6.1 选型结论

| 方案 | 判断 |
|------|------|
| Bun（Tot Clock 原 `server.ts`） | ❌ 需新装运行时，没必要 |
| 云数据库（Supabase/Firebase） | ❌ 孩子作息数据上云，隐私风险 + 过度设计 |
| **Node 原生 http + SSE + JSON 文件** | ✅ **选这个** |

**理由**：
1. **Node v22 本机已有**，零新增运行时
2. **零第三方依赖**（不装 Express），供应链风险为零
3. 数据只落**本机 JSON 文件**，不出局域网
4. **关键洞察**：因为是挂钟模型而非倒计时模型，**时间游标每台设备用自己的系统时钟算，根本不需要同步**。需要同步的只有「配置」这一份数据 —— 同步压力极小
5. **SSE（Server-Sent Events）** 单向推送完全够用：手机改配置 → 平板秒更新。比 WebSocket 简单得多

### 6.2 架构

```
   手机 / 电脑（配置端）
        │  POST /api/config
        ▼
   ┌─────────────────────┐
   │  Node server (零依赖) │
   │  state.json  本地文件 │
   └─────────────────────┘
        │  SSE /api/events（配置变更实时推送）
        ▼
   挂墙平板（展示端）
        │
        └── 游标位置自己用系统时钟算，不依赖网络
```

**接口**：
| 接口 | 用途 |
|------|------|
| `GET /api/config` | 拉取配置 |
| `POST /api/config` | 保存配置（并广播给所有设备） |
| `GET /api/events` | SSE 长连接，接收配置变更推送 |
| `POST /api/announce` | 播报去重登记（见下） |

### 6.3 多设备播报去重

手机 + 平板同时开着会**重复播报**。解决：
- 服务端按 **(日期 + 节点ID + 提醒类型)** 记录已播报，同一提醒只触发一次
- 每台设备另有**独立播报开关** —— 你决定哪台出声（比如只让挂墙平板出声）

### 6.4 运行方式

| 场景 | 命令 |
|------|------|
| 开发 | `npm run dev`（Vite 代理 `/api` → Node 服务） |
| 生产 | `npm run build` + `node server/index.js` |
| 平板访问 | `http://<电脑局域网IP>:3000` |

## 8. 新时间轴的边界条件清单

这些是 Tot Clock **没覆盖**的（它模型里根本不存在），我会逐个实现：

| # | 边界条件 | 处理策略 |
|---|---------|---------|
| 1 | **跨夜**：睡觉 20:30 → 次日 07:00 | 时间轴做闭环，弧段处理 wrap-around |
| 2 | **当前时间在睡觉弧上** | 游标沿弧移动，剩余时间 = 距起床 |
| 3 | **零点 rollover** | 系统跨天时自动翻到新的一天，已播报记录清零 |
| 4 | **节点跨夜排序** | 不能按时间字符串简单排序，需归一化到"距起床的分钟数" |
| 5 | **节点时间冲突/乱序** | 保存时自动按时间重排，冲突节点高亮提示 |
| 6 | **配置为空 / 只有 1 个节点** | 兜底展示默认作息，不白屏 |
| 7 | **系统时间被改** | 游标跟随系统时间，不做校准（避免复杂度） |
| 8 | **TTS 未激活** | 首次交互前显示"点一下开启声音"提示 |
| 9 | **多设备重复播报** | 服务端按 (日期+节点ID+类型) 去重 |
| 10 | **页面后台被节流** | 切回时用 `Date.now()` 补算游标位置（复用漂移补偿） |
